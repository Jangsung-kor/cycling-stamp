# 6년차 풀스택 개발자를 위한 맞춤형 룰

이 프로젝트(`C:\vue3\cycling-stamp`)에서 에이전트는 6년차 풀스택 개발자와 페어 프로그래밍을 진행합니다. 다음 규칙을 항상 엄격하게 준수하십시오.

## 1. 시니어 레벨 커뮤니케이션 (No Fluff)
기초적인 언어 문법이나 뻔한 작동 원리에 대한 설명은 절대적으로 생략합니다. 코드를 즉시 제시하고, '어떻게(How)' 작동하는지 보다는 **'왜(Why)' 이런 구조를 선택했는지(트레이드오프, 디자인 결정, 대안 등)**에 대해서만 핵심 위주로 설명하세요.

## 2. 풀스택 관점의 부수 효과 고려 (Full-stack Mindset)
프론트엔드 또는 백엔드 어느 한쪽의 코드를 수정하거나 제안할 때, 단편적으로 접근하지 마세요. 반드시 반대편 영역(API 스펙 변경, DB 마이그레이션, 클라이언트 상태 관리 파급 효과 등)에 미치는 영향을 함께 검토하고, 필요한 변경 사항이나 사이드 이펙트를 선제적으로 제안하세요.

## 3. 선제적 리팩토링 및 최신 프랙티스 (Proactive Refactoring)
요청된 기능 추가나 버그 수정에만 그치지 마세요. 수정하는 코드 주변에 유지보수성을 높이거나 모던 아키텍처/디자인 패턴을 적용하여 개선할 수 있는 부분(기술 부채)이 보인다면, 선제적으로 리팩토링 방향을 제안하세요.

## 4. UI/UX 디자인: 아이콘 남발 금지 (Restrained Icon Usage)
* **아이콘 및 이모지 남발 절대 금지**: 버튼, 텍스트 라벨, 뱃지, 카드 헤더, 토스트 메시지 등에 무분별하게 장식용 이모지(예: 🚲, 🗺️, ⚡, 📋, 🏪 등)를 습관적으로 덧붙이지 마십시오.
* **명확한 시각적 식별 목적에만 한정**: 지도 마커나 하단 내비게이션 탭바처럼 콤팩트한 공간 내 필수적인 시각적 단서(Affordance)가 요구되는 영역에만 엄선하여 최소한으로 사용합니다.
* **미니멀 & 타이포그래피 중심 UI**: 불필요한 시각적 노이즈를 최소화하고, 정갈한 텍스트와 레이아웃, 여백 중심으로 가독성을 극대화하여 라이더가 핵심 주행 정보에 직관적으로 집중할 수 있는 절제된 모던 디자인을 유지하십시오.

## 5. 공통 스타일 우선 원칙 (Common Style First)
* **신규 기능 커스텀 스타일 임의 생성 금지**: 앞으로 새로운 기능이나 컴포넌트를 개발할 때 컴포넌트별 `<style>`에 하드코딩된 색상/패딩/폰트를 커스텀으로 만들지 마십시오.
* **디자인 시스템 및 CSS 변수 100% 재사용**: `src/styles/` 내의 공통 디자인 토큰 클래스(`.cycling-chip`, `.cycling-badge`, `.cycling-fab`, `.cycling-glass-card`, `.cycling-btn-subtle`, `.tabular-nums` 등)와 테마 CSS 변수(`var(--text-main)`, `var(--text-sub)`, `var(--brand-color)`, `var(--card-bg)`, `var(--border-color)`)를 최우선으로 재사용하여 모든 테마(라이트/다크/스탬프 잉크)에서 일관된 명도 대비와 가독성을 보장하십시오.
